4. 具体问题与复验
P0 — 当前未发现已证实的、阻断 SERENITY 单案例演示的问题
这是在材料与既有实际截图范围内的判断，不是本环境已执行过完整浏览器回归的保证。
P1 — Campaign 同路径切换后的侧栏上下文同步：静态代码发现风险，需定点复验
- 位置：`AppShell.tsx`、`LibraryPage.tsx`、`workspace-routes.ts`。
- 观察：`AppShell` 使用 useEffect(..., [pathname]) 才从 window.location.search 更新左栏 contextQuery。而 LibraryPage 的 Campaign 筛选使用 router.replace('/library?...')，可以只改变 query、不改变 /library pathname。因此用户在 Creative Library 内由 A 切换 B 时，左栏导航 href 可能继续指向 A，与当前筛选 Campaign 不一致。另外如果旧 query 带 scenarioVersion=1.1.0，换到 B/C 时这个版本可能仍被保留。
- **影响：**违背“所选 Campaign 在各工作区持续一致”的重要产品约束，尤其是用户自主探索 B/C 时。
- 证据等级：静态源码明确提示的风险；本会话未现场复现，现有 E2E 主要覆盖从带固定 query 的页面跨 pathname 导航，未证明“同 pathname 切换 Campaign 后再点击左栏”。
- **最小修复：**使 Shell 使用随 URL query 变化而响应的 search params / 路由状态；Library Campaign 变更时清理或重新选择 scenarioVersion、versionId/sessionId；新增一条 Playwright 测试，按 A→B→左栏 Atelier/Deliverables→刷新→返回，断言 campaignId / scenarioVersion / language 不回退或串用。
- **复验条件：**测试在本地实际浏览器通过，提供测试日志和目标链接/截图。若现场确证无 bug，可直接记录不需修复。
P2 — 保持视觉品质的低成本优化（非阻断）
