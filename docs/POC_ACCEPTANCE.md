# Fully Mocked POC 端到端验收标准

> 当前执行强度以[Demo快速交付规则](DEMO_DELIVERY_POLICY.md)为准。下列测试矩阵作为参考和最终检查目录，不要求每轮完整执行或为边缘缺项反复阻塞；主链功能、实际视觉与Mock标识保留。

此文件定义将来的验收，本次契约交付不表示业务完成。旧M0/TASK-006验收仅保留其原范围；TASK-007交付报告不等于主控通过。

## 内容与工程门禁

G0：Schema/所有字段、typed refs、API、事件、状态机、任务图一致；数据校验器正/负测试通过。G1：场景A十文件+实际素材到齐，五层验证与主控内容审核通过。G2=M1：有限四步原型在实际浏览器截图与交互审查通过、PO体验确认，才扩展更多页面。G3：A完整功能路径通过。G4：B/C各自完整四步与全流程演示通过。契约基础开发不受G2阻塞，大规模UI开发受G2阻塞。

## 黄金路径（A，5–8分钟）

1. 打开首页，三场景明确状态，选A创建新会话。所有步骤始终可见Mock标识。
2. 播放采集事件，查看信号、趋势与证据；1×/2×/4×、暂停/step/seek表现一致。观察分析前不能直接显示后续结果。
3. 查看完整事先推演依据、Brief和EN/AR脚本。保存一个本地编辑版本；刷新后仍在；缺匹配视频的派生稿被正确阻止。明确切回预置脚本并确认，原稿和编辑稿都保留。
4. 播放模拟渲染过程，真实预置MP4可播放、定位四镜头、结束、下载、封面下载；对应脚本/视频ID一致。
5. 查看模拟邮件、`.invalid`收件人和精确附件；确认模拟交付，产生一条本地Simulated delivered记录。双击/重试同key不多记；可显式演示一次失败后重试成功，两个attempt都有记录。
6. 下载真实交付ZIP与运行记录，解压、打开媒体、核对脚本与回执。刷新/关闭重开恢复会话。演示没有对外发送请求。
7. 从任意游标重放到结尾，用户交付记录数量不增加；单会话重置，另一个场景/会话和壳体偏好保持不变，再跑A结果一致。

## 视觉与交互

HTML最高权威，继续 `docs/DESIGN_SYSTEM.md` 与 `design/tokens.css`；不另造科技蓝紫、密集KPI/大聊天框。四步页面规格见 `docs/pages/POC_WORKFLOW.md`。1440×900、1366×768、1920×1080、390×844；主控实际打开截图，检查字体实际加载、AR RTL、留白、比例、对比度、焦点、表单校验、浮层回焦和脏稿保护、loading/empty/error、200%和Reduced Motion。

每轮证据：源文件hash或commit、包hash/version、session/游标/版本、浏览器/viewport/DPR、截图、控制台/请求/交互记录、命令exitcode、NOT_RUN清单。P0/P1/P2清零；P3记录接受理由。DSH只能提交review，主控核对代码和浏览器，修复后复拍，PO体验确认才更新总gate。

不接受：用动画代替状态机；随机文案；页面各写一套数据；脚本与成片不对应；假下载；预置视频声称实时生成；模拟邮箱声称真实投递；只看代码就视觉通过。
